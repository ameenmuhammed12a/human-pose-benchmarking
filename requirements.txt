# ---- MediaPipe Pose (BlazePose, 33 landmarks) -------------------------------
# The project brief specifies mediapipe==0.10.14 for the legacy
# `mp.solutions.pose` API, which bundles its models and works offline.
# That release only publishes wheels for CPython 3.8-3.12. On Python 3.13+
# it cannot be installed, and mediapipe 0.10.30+ no longer exposes
# `mp.solutions` at all -- only the newer `mediapipe.tasks` API.
#
# The notebook's MediaPipeWrapper handles BOTH: it tries `mp.solutions.pose`
# first and falls back to `mediapipe.tasks.PoseLandmarker`. Both produce the
# same 33-landmark skeleton, so results are unaffected either way.
#
#   Python 3.8 - 3.12  ->  uncomment the pinned line, get the legacy API
#   Python 3.13+       ->  keep the unpinned line, get the Tasks API
#
# mediapipe==0.10.14
mediapipe>=0.10

# ---- OpenPose ---------------------------------------------------------------
# NOT pip-installable. OpenPose is a C++ project and must be built separately
# with BUILD_PYTHON=ON, which produces the `pyopenpose` module:
#     https://github.com/CMU-Perceptual-Computing-Lab/openpose
# A CPU_ONLY build is sufficient. After building, download the BODY_25 model into
# <openpose>/models/ and set OPENPOSE_ROOT in the notebook's configuration cell.
#
# No build is needed to run this benchmark. OpenPoseWrapper falls back to CMU's
# OWN released COCO-18 weights (pose_iter_440000) executed through an equivalent
# PyTorch graph -- same network, same part affinity fields, same limb grouping,
# different executor. This is the path the committed results use. Fetch the
# weights (209 MB, into models/openpose_body_coco18.pth) with:
#     python tools/setup_data.py --only openpose
# It needs nothing beyond torch and scipy, both already required above.
# If neither a build nor the weights are present, the wrapper reports itself
# unavailable and is skipped without error -- the rest of the benchmark runs.
